# Remaining risks and unverified scope

This report separates implemented fixes, demonstrated limitations and suspected risks. The final suite contains 295 passing library tests, including 33 new regressions. Some existing PCB fixtures were corrected to use actual pads rather than the defective body-origin fallback. Passing them is not evidence of exhaustive correctness. No P4 feature expansion was undertaken; device metadata and manufacturing guards support the requested correctness work.

| Priority / classification | Source evidence | Remaining work / evidence needed |
|---|---|---|
| P0/P1 suspected durability/concurrency risk | `src/storage/save.rs::{write_with_backup,temporary_path_for,rotate_backup_generations}` uses a fixed sibling temporary path, file sync and rename, and separate backup rotation. | Concurrent writers/processes can compete for the same temporary/backup files; directory sync/power-cut guarantees are not established. Unique exclusive temp creation, serialized writers, fault-injected crash/power-cut tests are needed. No concurrent-write failure was reproduced in this audit. |
| P0 unverified malformed-data edge | `src/app/actions.rs::repair_saved_page`, `repair_saved_annotations` repair duplicate IDs and legacy endpoints. | Exhausted identity rejection is covered; ambiguous duplicated IDs with explicit references need adversarial migration fixtures and an explicit reject/repair policy. Do not assume repairing IDs preserves ambiguous references. |
| P0/P2 established manufacturing limitation | `src/export/gerber.rs`, `src/app/actions.rs::export_pcb_fabrication_files` | Experimental, limited layer/shape subset, no independent reader or fabricated sample, no PTH/NPTH distinction, no mask/paste/silk checks. Keep the experimental status until external interpretation and manufacturing feedback agree. |
| P0/P2 unsupported copper | `src/pcb/copper.rs::pad_islands`, `src/export/gerber.rs::manufacturing_limitations` | Copper zones are not solved/exported; advanced pad shapes/package mappings require metadata and tests. Current guards reject unsupported manufacturing instead of silently claiming connectivity. |
| P1 established numerical-model limitation | `src/engine/mna/dc.rs::solve_dc_profiled_internal`, `ac.rs::solve_ac_with_connectivity`, `transient.rs::solve_transient_with_netlist` | Piecewise diodes/MOS switches, simplified AC rather than full bias linearization, single-RC analytic transient. Need trusted analytic/SPICE comparisons, ill-conditioning sweeps and convergence-failure fixtures before widening accuracy claims. AC still lacks the same structured error/scaling surface as DC. |
| P1 unverified numeric extremes | `src/engine/mna/matrix.rs` row/column equilibration and resistance floor; `src/export/gerber.rs::coord` | Near-zero branch current uses regularization. Broad dynamic-range, dependent-source and nonlinear oscillation tests remain. Gerber's declared 4.6 coordinate range needs an explicit boundary gate; i64 removes the old narrow integer saturation but not the format bound. |
| P1 metadata/cache design debt | `src/engine/worker.rs::WorkerCache`, `src/model/net.rs::with_component_properties` | Structural ERC is conservatively regenerated on every electrical edit because its dependency labels were incomplete. Preserve this correctness behavior until rules declare all value/label dependencies. Topology remains reused; returned canonical pin metadata is a topology-time snapshot, so consumers needing current values must use the property projection. |
| P1/P2 established profile gaps | `src/model/device.rs`, existing `src/model/component.rs::electrical_metadata`; ERC/codegen | Only verified subsets, generic Nucleo unknown MCU, ESP/Blue Pill clone headers unspecified, package/current ratings missing. Existing legacy heuristics are not fully migrated. Full pin tables/board revisions, ADC/bank/current/thermal/boot behavior and firmware compile/device tests remain. |
| P1/P2 ECO review requirement | `src/pcb/board.rs::{apply_eco_patch,remap_copper_nets}` | Unique surviving/merged pin sets preserve copper; splits/unknowns orphan it. Footprint replacement may physically invalidate old routes despite preserved coordinates. Package replacement, split/merge, zones and multi-step command undo need broader fixtures. Export guards are necessary, not a substitute for reviewing ECO geometry. |
| P2 established DRC performance regression | `src/pcb/drc.rs::run_drc_with_nets`; `src/pcb/copper.rs::pad_islands` | Full shape/layer checks use broad pairwise scans. Measured full DRC grew by roughly two orders of magnitude; spatial broad-phase and cancellable full DRC are the next optimization. See measured table. |
| P2 interactive/export mismatch limitation | `src/pcb/drc.rs::run_local_drc`, `src/app/actions.rs::refresh_local_pcb_analysis`, `export_pcb_fabrication_files` | Interactive local DRC is a subset, followed by full worker validation. Fresh full export gate is correct but synchronous. Add explicit pending/cancel/progress UX and large-board interaction tests. |
| P2 undo-memory estimate limitation | `src/editor/delta.rs::approximate_board_metadata_cost` and snapshot/history accounting | New net bindings include nested allocations, but existing library/zone/string accounting is still partly shallow. A 16 MiB estimate does not imply a strict process-heap bound. Measure deep metadata histories and account nested allocations. |
| P2 bundle atomicity limitation | `src/app/actions.rs::export_pcb_fabrication_files`, `src/storage/save.rs::write_with_backup` | Each export file is atomic; the whole multi-file bundle is not transactional. Stage a generation directory and publish a manifest only after all files succeed. |
| P3 unverified GUI scope | `src/ui/app/mod.rs::update_ui`, `src/ui/pcb_workspace.rs`, inspector | Offscreen production painting and existing narrow/empty breadboard test passed. Actual desktop gesture flow, inspector width and all empty/narrow workspaces were not manually inspected. |
| P3 benchmark confidence boundary | `examples/performance_probe.rs`, `src/performance.rs` | One before and one after local run, nine samples each, no interleaved trials/hardware isolation. Synthetic no-ground analysis is preparation/failure handling, not a successful solver benchmark. No GPU-present or real user-input latency measurement. |

The baseline Git revision and successful final commands are recorded in [architecture-audit.md](architecture-audit.md) and [verification.json](verification.json). The checkpoint improves demonstrated data and electrical failures; it does not close every invariant or certify all boards, solver models or fabrication outputs. Next work should remain on correctness gaps and DRC scalability before new product features.
